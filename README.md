# FISCHXR website (by ReelWorks)

## Settings (top of `gen_site.py`)

| Setting | What it does |
|---|---|
| `SERVICE` | Your FISCHXR service. The live numbers come from it, and the Download buttons go through it so downloads are counted. |
| `VERSION` | The version shown under the Download buttons. Change it with each release. |
| `TRAILER_YT` | A YouTube video ID for the trailer (the part after `v=` in a YouTube link). Empty shows a "Trailer coming soon" frame. |
| `SITE_URL` | The site's address once it's online. Needed for the picture in Discord link previews. |
| `TEAM` | The people on the About page: name, role, one line, and optionally a picture (put pictures in `assets/team/`). **Replace the placeholders before going live.** |

After changing any of them, run `python gen_site.py` in this folder to rebuild every page.

**Downloads:** the buttons point at `SERVICE/download`, which counts the download and sends people on to the file. Set the service's `DOWNLOAD_URL` variable to the address of your hosted `download/FISCHXR.exe` (see the service README).

**Changelog:** `changelog.html` is built from the `CHANGELOG` list at the bottom of `gen_site.py` (taken from the macro's own release notes). Add each new version to the top of that list.

Four pages, plain files, no build step. Keep the folder together and double-click `index.html` to open it from your disk.

## Pages

| Page | What's on it |
|---|---|
| `index.html` | Home: the live reel, the download buttons (centered), the rod shelf, the Free vs Plus chart, and a short "made by ReelWorks" note |
| `rods.html` | Every special rod: its render, what's odd about its reel and what FISCHXR does |
| `features.html` | Totems, Aquarium, Sovereign, Alerts and Reel settings, each with its app screenshot |
| `changelog.html` | Every update, newest first; older versions fold away |
| `about.html` | Who makes FISCHXR: the team cards (from `TEAM`), how ReelWorks works, and how to help |
| `download.html` | The download, centered, with three steps and a note about the Windows warning |
| `404.html` | Shown for pages that don't exist (Cloudflare Pages and GitHub Pages both use it automatically) |

Every page shares `assets/site.css` (the look) and `assets/site.js` (the scroll-progress line, things easing in, counters and the live reel).

## The download

Every Download button points at **`download/FISCHXR.exe`**. Put the file there with exactly that name. If you name it differently, search the pages for `download/FISCHXR.exe` and change it.

The download page warns people that Windows may show "Windows protected your PC" for a new, unsigned app, and tells them how to continue. If you ever buy a code-signing certificate, remove that note.

## Pictures

| Folder | What it holds |
|---|---|
| `assets/renders/` | Your rod renders (transparent PNGs), named by rod: `noiseform.png`, `pinion.png`, `verdant.png` and so on |
| `assets/app/` | Your angled app screenshots: `totems`, `aquarium`, `sovereign`, `alerts`, `reel` |

## Rod colours

Each rod has a colour in the `RODS` list in `gen_site.py` (for example `"#3FA8FF"` for Poseidon's Lance). Pointing at a rod anywhere on the site makes the page glow in that colour.

## Adding a rod

The pages are generated by `gen_site.py` (run `python gen_site.py` in this folder after editing its lists), or you can edit the HTML directly: copy one `<article class="rod">` block in `rods.html`, change its `id`, picture and text, add a tile for it in the grid at the top of that page, and add it to the shelf on `index.html` (the shelf lists every rod twice so the loop is seamless).

## Hosting it later

Any static host works:

- **GitHub Pages:** put the folder in a repository and turn on Pages.
- **Cloudflare Pages:** upload the folder as a Pages project, next to the FISCHXR service you already run there.

Large downloads can also live on GitHub Releases or Cloudflare R2, with the buttons pointing there instead.

## On phones

Below tablet width the menu becomes a button at the top right that opens a full-screen menu. The comparison chart scrolls sideways on narrow phones rather than squeezing, and buttons go full width on the smallest screens.
